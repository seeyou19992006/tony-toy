## MacDeck 按需启动改造（Home 键交给 TonyToy）

**动机**：常驻内存 63.6 MB → 31 MB。MacDeck 只在要玩的时候才起。

**架构分工**（关键，别搞混）：
- **按键所有权**归 TonyToy：`src/HomeKeyBridge.swift` 用 IOHIDManager 读原始报告，Home 按下就发意图。
- **状态所有权**归 MacDeck：收到 `com.sunxiaolong.macdeck.toggle` 通知自己 toggle，别人不许猜它可见性。
- TonyToy 新增 `AppAction.toggleApplication(bundleIdentifier:)`（配置名 `toggle_application`），
  逻辑：进程没跑 → `NSWorkspace.openApplication` 带 `--show-deck`；在跑 → post `<bundleID>.toggle`。带 0.6s 防抖。
- MacDeck 删掉了整套原始 HID 层（`setupRawHID`/`attachRawDevice`/`handleRawReport` 等约 60 行）
  和 Home 绑定，只保留 `preferredSystemGestureState = .disabled` 压制系统手势。
- MacDeck 新增空闲退出：大屏收起后 `config.idleExitMinutes`（默认 10）分钟无操作就 `NSApp.terminate`。

**踩的坑（都实测过）**：
1. **多手柄共用一块报告缓冲区会导致数据串台**。原来照搬 MacDeck 的单一静态 buffer，
   机器上同时接了 Pro Controller 和 Stadia，两边报告互相覆盖，于是 `data[4]` 在 0x00/0x10 之间
   以 62Hz 震荡，Home 一秒触发 40+ 次（Stadia 的 0x79 被当成 Home 按下）。修法：**每台设备独立 buffer**，
   并且 **只处理 reportID == 0x30**（0x03 等其他报告里 byte4 不是按钮组）。
2. **摇杆漂移会无限重置空闲计时**。这手柄静止时也持续冒方向事件，若算作"活动"进程永远退不掉。
   修法：`DeckStore.isStickKey()` 把四个摇杆方向键排除在 `onActivity` 之外。
3. 旧配置里 `hotkeyChord = [13]`（Home），必须过滤，否则同一颗键两个进程各响应一次。
   `DeckConfig.init(from:)` 里 `filter { $0 != homeKeyCode }`，学习组合键时也拦。
4. 覆盖安装时如果旧进程还在跑，它持有旧 inode，`ps` 显示新路径但跑的是旧代码 —— 排查问题前先 `pkill`。

**实测数据**：
- 冷启动到大屏就绪 **337ms**。
- 手柄 HID 读取**不需要任何 TCC 授权**（裸 CLI 程序即可读取，MacDeck 的 Info.plist 也从没有 Input Monitoring 声明）。
- 空闲退出精确：计时 62 秒后退出。
- 内存：TonyToy 29.3 → **31 MB**（+1.7，含 IOKit），MacDeck 28 MB 按需。
